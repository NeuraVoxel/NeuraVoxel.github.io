## 一、驾驭层的定位

模型是能力，驾驭层是把能力变成生产力的制度。

单靠 Prompt 调用模型，能做出惊艳的 Demo，做不出可交付的系统。原因很简单：**模型负责生成，不负责边界；负责可能性，不负责后果。** 边界、后果、可追溯性，都要靠模型外围的那一层来提供。

驾驭层（Harness）就是这一层。它不是某个具体的 SDK，而是一套需要被明确设计的工程结构。本框架把它拆成七要素，每一个要素都必须有明确的设计决策，而不是默认缺省。

> 模型是发动机，驾驭层是整车——发动机决定能跑多快，整车决定能不能上路。

## 二、七要素

### 1. 规划（Planning）

**要解决的问题**：开放的生成任务如何被拆成可约束的子任务。

- 任务拆解的粒度：过粗则无法校验，过细则编排成本失控
- 计划的表示：必须是结构化的、可被后续环节消费的中间产物
- 计划失败的处理：重规划次数上限与降级路径

### 2. 约束（Constraints）

**要解决的问题**：采样空间如何被缩小到可接受区间。

- 输出结构约束：Schema / 类型 / 枚举，让输出可被程序消费
- 风格与事实锚定：示例锚定风格，知识注入锚定事实
- 越权约束：明确不可做的事，而不是列举可做的事

### 3. 工具（Tools）

**要解决的问题**：模型如何安全地作用于外部世界。

- 工具契约：参数校验、幂等性、超时与重试
- 最小权限：工具能做什么，由能力清单界定，不由 Prompt 界定
- 副作用分级：只读 / 可重试写 / 不可逆写，分级配置审批

### 4. 知识（Knowledge）

**要解决的问题**：模型的通用知识如何与企业的事实对齐。

- 知识来源分级：权威源、业务源、用户生成内容，可信度不同
- 时效与版本：知识不是越多越好，过期知识的危害大于缺失
- 检索判据：命中不等于可信，需要可信度与冲突消解策略

### 5. 护栏（Guardrails）

**要解决的问题**：错误如何在到达用户之前被拦截。

- 校验层次：格式校验、事实性校验、合规校验、一致性校验
- 拦截动作：阻断、降级、转人工，按风险等级配置
- 拦截留痕：每一次拦截都要可归因，否则无法收敛

### 6. 编排（Orchestration）

**要解决的问题**：单点波动如何被流程冗余吸收。

- 控制流归属：关键控制流由代码接管，不让模型自己决定下一步
- 重试与回退：失败在哪里重试、重试几次、何时转人工
- 可重跑性：同一输入重跑，产物差异在阈值内

### 7. 观测（Observability）

**要解决的问题**：系统行为如何被看见、被归因、被复盘。

- 链路日志：模型版本、检索依据、工具调用、校验记录、审核人
- 指标体系：通过率、拦截率、人工干预率、漂移监测
- 复盘闭环：拦截与人工修改回流，驱动 Prompt、规则与知识更新

## 三、分层结构

七要素不是平铺的，而是分三层：

| 层 | 要素 | 稳定性 | 变更频率 |
| --- | --- | --- | --- |
| 制度层 | 护栏、观测 | 高 | 低，变更需评审 |
| 流程层 | 编排、规划 | 中 | 中，随场景迭代 |
| 能力层 | 工具、知识、约束 | 低 | 高，随业务演进 |

越靠下变更越频繁，越靠上越需要被保护。制度层是最不该被频繁改动的一层——护栏与观测一旦随业务随意调整，收敛就无从谈起。

---

## 四、设计原则

**1. 控制流归代码，生成归模型。** 关键分支、循环与终止条件由确定性代码控制，模型只负责它擅长的生成与判断。

**2. 先分流，再设计。** 确定性任务不该进驾驭层——能枚举、可演绎的，交给规则直接求解；驾驭层只处理真正需要生成的任务。

**3. 错误要拦在便宜的地方。** 输入侧能拦的不要留到输出侧，模型调用前能拦的不要留到调用后。

**4. 责任永远在人。** 高风险环节 AI 只作辅助，人类判断并签字；任何自动化都不能消除责任主体。

**5. 不可观测即不可收敛。** 没有链路日志，就没有归因；没有归因，闭环就转不起来。

## 五、与四道防线的对应

驾驭层是工程化收敛体系的技术实现，两者一一对应：

| 四道防线 | 驾驭层要素 |
| --- | --- |
| 数据治理 | 知识 |
| 工作流编排 | 规划、编排 |
| AI 护栏 | 约束、工具权限、护栏 |
| 人机审核 | 编排中的转人工路径、观测中的审核留痕 |

体系回答"要设哪些防线"，驾驭层回答"这些防线在技术上怎么落地"。

## 六、验收清单

- [ ] 每个开放任务都有结构化计划产物，可被后续环节消费
- [ ] 输出受 Schema 约束，可被引擎程序化校验
- [ ] 工具按最小权限配置，副作用已分级
- [ ] 知识源有可信度分级与时效管理，检索冲突有消解策略
- [ ] 护栏按风险等级配置拦截动作，拦截记录可归因
- [ ] 关键控制流由代码接管，流水线可重跑
- [ ] 任意一次输出可在限定时间内还原完整链路
- [ ] 拦截与人工修改已回流，驱动下一轮迭代

判断驾驭层是否设计到位，只有一个标准：**换一个更强的模型，系统是变好了，还是失控了。** 前者说明制度成立，后者说明只是碰巧跑通。
