# NeuraVoxel 产品门户站点设计

**日期：** 2026-08-26  
**状态：** 已批准（对话确认 §1–§5）  
**仓库：** `NeuraVoxel/NeuraVoxel.github.io`（域名 `neuravoxel.cn`，GitHub Pages）

## 1. 目标与定位

建设 **产品门户 + 轻量能力入口** 站点：对外讲清以自动化数据引擎为核心的产业数据闭环，对内（技术读者）提供模块介绍与 Markdown 文档。

| 维度 | 决策 |
|------|------|
| 定位 | 门户叙事 + 模块/文档入口；真实训练/仿真/标注仍外链至外部系统 |
| 受众 | 首页偏产业客户；模块与文档服务技术读者 |
| 能力深度 | 叙事、架构图、文档与外链；**不做**站内真实任务操作 |
| 语言 | 中英双语；**默认路由为中文**（`/`）；英文前缀 `/en/...` |
| 频道 | **模块/工具** + **文档** 两套；v1 **不做**独立日常开发日志（由文档 `releases`/Changelog 承担） |
| 内容准备度 | 骨架 + 首批真实内容（2 个产业场景、若干模块、可渲染 MD 含版本说明） |

### 1.1 非目标（v1）

- 用户登录、鉴权拉数、真实 DMP 控制台
- DDS / 服务化接口的实连与任务提交
- 独立 `/journal` 开发日志频道
- 完整多产业目录（仅先做自动驾驶、具身智能）
- SSR、后端 API

## 2. 信息架构

### 2.1 路由（中文默认）

| 路由 | 用途 |
|------|------|
| `/` | 首页：品牌、DMP 中枢闭环叙事、产业场景、模块/文档入口 |
| `/modules` | 模块/工具列表 |
| `/modules/[slug]` | 单模块：产品介绍、下载、外链 |
| `/docs` | 文档首页 / 目录 |
| `/docs/[...slug]` | Markdown 文档（使用说明、版本发布等） |
| `/en`、`/en/modules`、`/en/docs/...` | 英文镜像 |

页脚：关于/联系（简短页或外链）、语言切换、版权。

### 2.2 内容落盘

- `src/content/modules/{zh,en}/*.md` — 模块介绍与链接元数据
- `src/content/docs/{zh,en}/**/*.md` — 使用说明与 Changelog
- UI 文案：`src/i18n/{zh,en}.json`
- 保留仓库根目录 `CNAME`（`neuravoxel.cn`）

## 3. 首页与数据闭环叙事

### 3.1 第一屏

单一构图（非仪表盘）：

- 品牌 **NeuraVoxel** 为英雄级信号
- 一句主张：以自动化数据引擎驱动产业数据闭环
- 一句支撑：训练 / 微调 / 仿真对接 / 标注对接
- CTA：`了解闭环`（锚点）+ `查看模块` / `阅读文档`
- 全幅视觉锚点（闭环动效或场景图）；无插卡式小图、无浮层徽章

### 3.2 第二节：闭环以 DMP 为核

**DMP（数据管理平台）是驱动标注、训练/微调、仿真等模块的数据中枢**，不是与环上能力并列的一步。

结构：

1. **中心：DMP** — 数据集组织、版本、权限、分发与回流
2. **环上能力（由 DMP 驱动）**：标注对接 → 训练/微调 → 仿真验证 → 数据回流 DMP
3. **DMP 与其他平台的交互方式**（首页摘要，细节进文档）  
   - **数据集组织与下载**：版本化数据集、清单校验、批量下载  
   - **服务化接口**：HTTP/API 供训练、标注、仿真拉数与回写元数据  
   - **DDS 通信**：实时/近实时流式通道（车端/机器人端或仿真侧）

示意图：DMP 居中；外环为标注 / 训练 / 仿真；连线标注「下载 / API / DDS」。

### 3.3 第三节：产业场景（v1）

- 自动驾驶
- 具身智能

每场景：痛点一句 + 数据如何进 DMP、如何被环上模块消费与回流 + 链到相关模块/文档。

### 3.4 第四节：能力入口

短句收束 + 两入口：**模块与工具**（DMP 置顶）、**文档与版本**。

### 3.5 视觉方向

深空灰 / 冷青数据感；克制动效（品牌入场、闭环步骤依次显现、场景淡入）；尊重 `prefers-reduced-motion`。避免紫白渐变、奶油衬线陶土风、报章密栏等常见模板味。英文页镜像同一结构。

## 4. 模块与文档内容模型

### 4.1 模块频道

列表排序：**核心 → 环上**；DMP 置顶并标记为核心。

Frontmatter 约定：

| 字段 | 说明 |
|------|------|
| `title` / `summary` | 名称与一句话介绍 |
| `role` | `core` \| `ring`（DMP = `core`） |
| `status` | `available` \| `preview` \| `planned` |
| `downloads[]` | `{ label, url, type }` |
| `links[]` | `{ label, url }`（控制台、仓库、文档锚点等） |
| `integrations[]` | 可选：`dataset_download` / `service_api` / `dds` 等（DMP 必填） |
| `industries[]` | 如 `autonomous-driving` / `embodied-ai` |
| 正文 | 产品介绍；长篇手册放文档站 |

**v1 首批模块（固定 slug）：**

| slug | role | 说明 |
|------|------|------|
| `dmp` | core | 数据管理平台（必有，内容相对完整） |
| `annotation-bridge` | ring | 标注平台对接 |
| `training-bridge` | ring | 训练/微调对接 |
| `simulation-bridge` | ring | 仿真平台对接 |

后三个可为 `preview` / `planned`，但介绍页齐全。

### 4.2 文档频道

Markdown 渲染（标题、代码块、表格、内链）；建议目录树：

```
docs/
  getting-started/     快速了解 NeuraVoxel 与闭环
  concepts/            闭环概念、DMP 中枢、交互方式总览
  dmp/                 数据集组织/下载、服务化接口、DDS 等使用说明
  integrations/        标注 / 训练 / 仿真对接（外链 + 站内步骤）
  releases/            版本发布与 Changelog
```

中英各一套；英文可先少译，缺页显示「暂无英文」并链回中文。

### 4.3 交叉链接

- 模块页 → 对应 `docs/...`
- 文档中的模块名 → `/modules/[slug]`
- 首页闭环图节点 → 模块或概念文档

## 5. 技术架构与部署

### 5.1 技术选型

- **Astro**，`output: 'static'`
- Content Collections：`modules`、`docs`
- Markdown/MDX；代码高亮（如 Shiki）
- 全局 CSS 变量 + 少量组件样式；不引入重型 UI 库
- 动效：CSS / 轻量 JS

曾评估 VitePress/Docusaurus（文档强、门户弱）与 Next 静态导出（偏重）；选定 Astro 以平衡营销首页、模块页与 MD 文档。

### 5.2 双语

- 默认中文无前缀；英文 `/en` 前缀
- 语言切换：同路径换 locale；缺译 → 提示 + 链中文
- UI 字符串与长内容分离（i18n JSON vs Content Collections）

### 5.3 仓库结构（要点）

```
src/
  pages/              # 含 en/ 镜像路由
  layouts/
  components/
  content/modules/{zh,en}/
  content/docs/{zh,en}/
  i18n/
  styles/
public/
CNAME                 # neuravoxel.cn
docs/superpowers/specs/  # 本设计文档等
```

### 5.4 部署

- GitHub Pages：`main` 经 Actions（或约定分支）发布静态产物
- 构建产物根目录包含 `CNAME`
- 本地：`dev` 预览；`build` 校验双语路由与内容集合

## 6. 错误处理与边界

| 情况 | 处理 |
|------|------|
| 未知路由 | 本地化 404，提供回首页/模块/文档入口 |
| 模块缺英文 | 提示「暂无英文」；回退或链到中文页 |
| 文档缺页、坏链 | 构建期尽量暴露；运行时 404 |
| 外链失败 | 目标站负责；站内保证链接可配置；`rel="noopener"` |
| 动效/图失败 | 不影响阅读；尊重 reduced-motion |

## 7. 验收标准（v1 Done）

1. `/` 呈现品牌 + **DMP 中枢**闭环叙事（含下载 / API / DDS 交互摘要）+ 两个产业场景 + 模块/文档入口  
2. `/modules` 含 DMP（`core`）及至少三个环上模块页；含介绍、下载/外链字段  
3. `/docs` 可渲染 MD；含概念、DMP 交互说明、`releases`/Changelog  
4. `/en/...` 可切换；默认语言为中文  
5. 静态构建可部署 GitHub Pages，`CNAME` 保留  
6. 桌面与移动端首页/列表/文档可读；无登录、无真实任务操作  

## 8. 后续（本设计范围外）

设计批准并完成实现计划后，再进入实现。可能的后续迭代（不在 v1 验收内）：补全英文文档、增加产业场景、模块状态从 preview 升为 available、真实控制台外链上线等。
